## О проекте

Мини-проект «Система агрегации и интеграции данных интернет-магазина» — программный модуль интеграции, который автоматизирует обмен данными между внутренней учётной системой торгового предприятия (например, складской CRM) и внешней торговой платформой (маркетплейсом или интернет-магазином).

Модуль должен обеспечивать:

- автоматическое обновление остатков товаров на торговой площадке;
- передачу статусов заказов и трек-номеров отправлений;
- синхронизацию каталога товаров;
- работу в режиме, близком к реальному времени.

## Структура репозитория

```
shop-integration/
├── src/            — исходный код модулей интеграции и бизнес-логики
│   ├── connectors/ — подключения к внешним системам (REST API, SFTP, БД)
│   ├── webhooks/   — приём входящих вебхуков о заказах
│   ├── parsers/    — разбор форматов CSV / XML / JSON
│   ├── models/     — внутренние сущности: товар, остаток, заказ
│   ├── services/   — бизнес-логика: валидация заказов, расчёт остатков
│   │   └── mapping/ — правила сопоставления данных (ПР №3)
│   └── utils/      — вспомогательные функции: логи, повтор запросов
├── config/         — файлы конфигурации подключений, фильтры импорта
├── tests/
│   ├── unit/        — модульные тесты (test_mapping.py — ПР №3)
│   ├── integration/ — проверка интеграционных связей
│   └── fixtures/    — тестовые данные (pr3/ — записи источников)
├── docs/           — проектная документация и отчёты (pr2/, pr3/)
├── scripts/        — служебные скрипты (run_mapping_demo.py — ПР №3)
├── pr4-skud/       — ПР №4: схемы JSON/XSD и C#-приложение СКУД
├── pr5-gitflow/    — ПР №5: сценарий Git Flow и граф коммитов
├── requirements.txt
├── .gitignore      — исключения из репозитория (.env, логи, venv, кэш, bin/obj)
└── README.md
```

Пароли, токены и ключи API в репозитории не хранятся: реальные значения задаются в файле `.env`, который исключён через `.gitignore`. Все персональные данные в тестовых примерах вымышленные.
